# v0.12.0 — 桌面个人试写版

本版交付单人、桌面、本地保存的章节创作流程：创建作品、保存思路、三个大纲方案、比较选择与编辑、确认准确版本、正文生成与修订、审阅、可选 Reader、本地定稿。实际发布状态以 [GitHub Release](https://github.com/WastonGura/GuraNovel/releases/tag/v0.12.0) 为准。

## 变化

- 统一正式前端，移除旧工作台；保留旧链接兼容及历史数据。旧 V1 任务仍只读。
- 设定文档软删除/恢复保留文档身份、正文、版本和引用，批量操作逐项反馈。
- 评论保存引用范围与来源版本；思路按作品/章节保存，冲突时保留本地文本。
- 每批三个大纲持久化任务、输入和上下文；选中的大纲成为独立文档，确认绑定准确版本，起草后锁定。
- 修复空白作品首次审阅、104 段长章修订/审阅、修订上下文和失败恢复；拒绝模型原样返回正文却声称完成修改。
- Reader 支持正常中文输入/输出预算，按验证后结果结算保守字节用量，并记录真实配置的 Provider；缺省题材不再假设为 fantasy。
- 创建作品表单、桌面设定布局、保存/阶段状态和能力说明完善。
- GitHub Actions 增加版本一致性及 Docker 经前端代理访问真实后端/PG 的作者流程；移除 Qodana。

## 验证与质量边界

[阶段验收记录](../acceptance/v0.12.0-desktop.md)包含确定性测试、Docker/界面边界和两个真实模型样本；[用量台账](../acceptance/v0.12.0-model-calls.json)保留耗时、token、输入/版本摘要与失败。

真实模型使用 deepseek-flash、reasoning_effort=none、120 秒单次超时。两个样本完成本地定稿，长样本还完成真实 Reader。方案有差异，具体修订可以落实，审阅可以提出具体建议；同时出现漏改、漏检矛盾、长度失控、无效结构与英文评语。因此本版适合个人试写和验证，模型意见必须由作者判断。多个审阅角色通过不保证作品正确。

默认 fake Provider 和关闭的 Reader 用于无密钥体验。真实配置方法及 Compose 覆盖文件见 [README](../../README.md#使用真实模型)。本地定稿不向外部发布作品。

## 从 v0.11.0 升级

保留原 Compose 项目名称、数据库卷和工作区卷。换目录或更改 `-p` 会选择另一组卷；请先记录当前项目名称、配置文件和提交。数据库记录与文件工作区必须配对备份/恢复。

1. 停止应用写入：`docker compose stop backend frontend`；数据库保持运行以导出备份。实际使用额外 `-p` / `-f` 时，每条命令沿用同一组合。
2. 在宿主机创建备份目录。以下 Bash 示例先在容器生成 dump 再复制，避免 PowerShell 文本管道损坏二进制数据：

   ```bash
   mkdir -p backups
   docker compose exec -T db pg_dump -U postgres -d guranovel -Fc -f /tmp/guranovel-pre-v012.dump
   docker compose cp db:/tmp/guranovel-pre-v012.dump ./backups/guranovel-pre-v012.dump
   docker compose run --rm --no-deps --entrypoint /bin/sh -v "${PWD}/backups:/backup" backend -c 'tar -C /data -czf /backup/workspaces-pre-v012.tar.gz workspaces'
   ```

   将配对备份复制到独立存储，并确认 dump 可列目录、归档可解包。备份包含小说正文，应自行妥善保管；模型密钥使用原有私密配置。
3. 在干净 checkout 切到已发布的 `v0.12.0` 标签；保留原环境配置，沿用原 Compose 项目名称。不要覆盖本地未提交修改。
4. 执行 `docker compose up -d --build --wait`，再检查 `docker compose ps`、前后端 `/api/v1/health`、已有作品与正文。
5. 新增迁移 `0012_setting_document_trash` 在 documents 表添加可空 deleted_at，旧记录保持有效；不删除文档、版本或引用。历史已发布迁移未修改。服务启动时执行 `alembic upgrade head`。

不要在升级时运行 `docker compose down -v`。不要为回退而直接 downgrade 0012：旧应用不理解回收站状态，且去掉标记会丢失删除状态。需要回退时，停止新应用，将升级前数据库备份和工作区备份恢复到一组隔离卷，再使用对应 v0.11.0 程序核对；确认恢复结果后再切换。不要将旧数据库与新正文目录混用。
