## Persistence implementation starting point

`DocumentService.write_document` / `restore_document` already lock the document and validate `expected_current_version_id`. Immutable versions support server-only `version_metadata`, currently strictly limited to contract/operation identity and optional attempt ID; public responses omit that metadata. Do not weaken this allowlist or expose arbitrary internal metadata to solve the UI need.

`StudioArchives.tsx` now lists explicit `studio_restore_points`, rather than every document version. Creating a point references the already-saved immutable draft version. Automatic saves do not create points. Migration `0006_studio_restore_points` preserves previously recognizable manual saves (`source=user`, `change_summary=手动存档`) as points; all original document versions remain untouched.

New project/chapter-scoped endpoints:

- `GET /projects/{project_id}/chapters/{chapter_id}/restore-points`
- `POST /projects/{project_id}/chapters/{chapter_id}/restore-points`
- `POST /projects/{project_id}/chapters/{chapter_id}/restore-points/{point_id}/restore`

POST requests contain `request_id` and `expected_current_version_id`, both non-nil UUIDs. The UI reuses the same request ID and inputs after an uncertain failure. Creation and restoration reject changed inputs for a repeated request; chapter/document row locks serialize concurrent requests. Restoration can read a point from an older draft document in the same chapter and writes a new version into the current draft. It reuses DocumentService file-write/commit handling and strict mechanical version metadata for replay identity. It does not expose internal metadata or grant workflow approval/publication.

It reuses DocumentService's staged version and existing file-backup/commit handling. A write failure rolls back the version, feedback and backup together. A repeated restore returns the original version without overwriting feedback edited after that restoration. Restoring a legacy point preserves current feedback and rechecks its anchors rather than fabricating old comments.
- Archive UI reads the point's actual feedback alongside its immutable prose version and rejects mismatched identities. Its requirements panel and comment dots are read-only; underlines/dots open the original comment in the existing panel, with existing text/container motion.
